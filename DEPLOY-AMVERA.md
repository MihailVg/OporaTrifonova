# Деплой в РФ: Amvera вместо Render

## Почему не Render

В сентябре 2026 года из России перестали открываться адреса Render из диапазона `216.24.57.0/24` — блокируются именно IP, а не только домен. Свой домен, направленный на Render, приведёт на те же адреса. Поэтому:

- открыть панель Render из РФ можно только через VPN/прокси;
- **главное** — сайт на `*.onrender.com` не откроется у вашей девушки, преподавателя и других пользователей в России.

Для учебного проекта нужен хостинг, который доступен в РФ. Ниже — самый близкий к Render вариант.

> Актуальность блокировки проверяйте сами: ситуация с блокировками меняется. Но на ноябрь 2026 Render из РФ недоступен.

## Что такое Amvera

[Amvera Cloud](https://amvera.ru) — российский PaaS: загружаете код (GitHub или файлы), платформа собирает Node.js-приложение, запускает его и выдаёт HTTPS-адрес. По смыслу — тот же Render, только в РФ и с оплатой в рублях.

Плюсы:

- серверы и данные в России — лучше для 152-ФЗ, чем зарубежный хостинг;
- Node.js, Docker, PostgreSQL, постоянное хранилище;
- HTTPS и домен;
- русская поддержка;
- оплата российской картой.

Минусы:

- **бесплатного тарифа навсегда нет**;
- «Пробный» тариф — около **170 ₽/30 дней** (0,1 CPU, 100 МБ RAM, 2 ГБ SSD);
- «Начальный» — около **290 ₽/30 дней** (0,25 CPU, 500 МБ RAM, 5 ГБ SSD);
- для PGlite и Node лучше брать «Начальный»: 100 МБ может не хватить.

Цены и лимиты могут меняться — сверяйтесь на [странице тарифов](https://docs.amvera.ru/general/price.html).

## Что уже добавлено в проект

В корне лежит `amvera.yaml`:

```yaml
meta:
  environment: node
  toolchain:
    name: npm
    version: 22

run:
  command: npm start
  containerPort: 3000
  persistenceMount: /data
```

- Node 22;
- запуск `npm start`;
- приложение слушает порт 3000;
- постоянное хранилище монтируется в `/data`.

Если файла `amvera.yaml` нет, Amvera попробует `Dockerfile`. У нас есть и он, но для Amvera лучше использовать `amvera.yaml` — он явно задаёт порт и постоянную папку.

## Шаг 1. Создать проект

1. Зарегистрируйтесь на [amvera.ru](https://amvera.ru) (российская почта/телефон, оплата российской картой).
2. Откройте [личный кабинет](https://cloud.amvera.ru).
3. **Создать проект** → тип **«Приложение»**.
4. Название: `opora-clinic`.
5. Тариф: **«Пробный»** на 30 дней для проверки или **«Начальный»** для стабильной работы.
6. Создайте проект.

## Шаг 2. Загрузить код

### Вариант A — через GitHub (удобно для обновлений)

Amvera умеет забирать код из GitHub по вебхуку.

1. В GitHub: **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Дайте токену доступ к вашему репозиторию и права:
   - **Contents: Read-only**;
   - **Webhooks: Read and write**.
3. В Amvera откройте проект → вкладка **«Репозиторий»** → подключение GitHub.
4. Вставьте токен, выберите репозиторий и ветку `main`.
5. Amvera покажет адрес вебхука и секрет. В GitHub: **Settings → Webhooks → Add webhook**:
   - Payload URL — адрес из Amvera;
   - Content type — `application/json`;
   - Secret — секрет из Amvera;
   - события — **Just the push event** (или push + workflow, как просит Amvera).
6. Сделайте любой push в GitHub. Amvera подтянет код и начнёт сборку.

Если что-то не сходится, официальная инструкция: <https://docs.amvera.ru/applications/git/webhooks.html>.

### Вариант B — загрузить файлы вручную

1. В проекте Amvera откройте **«Репозиторий» → Code**.
2. Загрузите файлы проекта **без**:
   - `node_modules/`;
   - `data/`;
   - `.env`;
   - `.git/`.
3. Убедитесь, что `amvera.yaml`, `package.json`, `server/`, `views/`, `public/` лежат в **корне**, а не внутри папки `sonya/`.

Это проще, но при каждом изменении придётся загружать файлы заново.

### Вариант C — git-репозиторий Amvera

В проекте Amvera есть свой git-адрес. Можно склонировать его, скопировать проект и запушить в ветку `master`:

```bash
git clone https://git.amvera.ru/<username>/<project>
# скопировать файлы проекта
git add .
git commit -m "Опора"
git push origin master
```

Точные команды и авторизация — в разделе [«Работа с Git»](https://docs.amvera.ru/applications/git.html).

## Шаг 3. Переменные окружения

В Amvera: проект → **«Переменные»** → добавьте:

```env
PORT=3000
NODE_ENV=production
TZ=Europe/Kaliningrad

DOCTOR_PASSWORD=ваш-пароль-для-врача
SESSION_SECRET=длинная-случайная-строка

TELEGRAM_BOT_TOKEN=токен-от-BotFather
TELEGRAM_CHAT_ID=числовой-id-@Sson1ta

PGLITE_DIR=/data/pglite
```

`SESSION_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Пароль и токены лучше хранить как **секреты** Amvera, а не как обычные переменные.

`PGLITE_DIR=/data/pglite` обязателен: без него PGlite попытается писать в папку приложения `/app/data`, которая теряется при пересборке. В `/data` данные сохраняются.

## Шаг 4. Сборка и запуск

Amvera:

1. Установит зависимости (`npm install`).
2. Запустит `npm start` из `amvera.yaml`.
3. Приложение слушает `0.0.0.0:3000`.
4. Откроет HTTPS-адрес проекта.

Проверьте:

- `/api/health` — должно быть `{"ok":true,...}`;
- `/` — главная;
- `/doctor` — вход по паролю;
- «Настройки» → «Отправить тестовое сообщение» — Telegram;
- «Загрузить демо-данные»;
- вход пациентки по коду `OP-DEMO-2026`.

## Шаг 5. Домен

Amvera выдаёт технический адрес. Свой домен `.ru` можно подключить в настройках проекта: добавьте домен, пропишите DNS-записи у регистратора, дождитесь HTTPS.

Для реальной клиники домен — не главное; важнее хостинг и база в РФ, согласия и уведомление РКН.

## Если нужен строго 0 ₽

Честно: стабильного бесплатного хостинга для Node.js + базы + HTTPS, который гарантированно работает в РФ, сейчас нет.

Что можно попробовать:

1. **QWINS free** — российский виртуальный хостинг: 256 МБ RAM, 1 ГБ диска, Node.js/MySQL, без поддержки. Теоретически может хватить для демо, но Node-приложение с PGlite на shared-хостинге — лотерея. Не рекомендую для защиты, если нет времени на эксперименты.
2. **Yandex Cloud** — приветственный грант/new-user trial; можно поднять Docker на маленькой VM, но это сложнее, ограничено по времени и требует карты.
3. **GitHub Pages** — бесплатно, но только статика. Наш сервер, база, кабинет врача и тревожная кнопка там не заработают. Можно сделать красивую витрину, но не выполнить ТЗ полностью.
4. **Render через VPN** — панель откроется, но сайт `onrender.com` у пользователей в РФ не откроется. Не решение.

Если бюджет 0 ₽ и нужен именно работающий сайт — самый реалистичный путь: **Amvera «Пробный» 170 ₽ на месяц** или **российский VPS за ~200–300 ₽/мес** (Timeweb Cloud, Beget, reg.ru) с нашим `Dockerfile`.

## Российский VPS как альтернатива

Если хочется полного контроля и постоянного диска:

1. VPS в РФ (Timeweb Cloud, Beget, reg.ru) — от ~200–300 ₽/мес.
2. Docker + наш `Dockerfile`:

```bash
docker build -t opora .
mkdir -p /srv/opora-data
chown 1000:1000 /srv/opora-data
docker run -d --name opora -p 80:3000 \
  -v /srv/opora-data:/app/data \
  --env-file .env \
  opora
```

3. Nginx/Caddy + HTTPS, домен.
4. Для боевого контура — PostgreSQL в РФ и юридический чек-лист.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| 502/503 | Приложение не слушает 3000; проверьте `PORT=3000`, `containerPort: 3000`, `npm start` |
| Данные пропадают после пересборки | `PGLITE_DIR` должен быть `/data/pglite`, а не `./data` |
| Сборка падает | `amvera.yaml` в корне; Node 22; `package-lock.json`; логи сборки |
| Telegram не отвечает | Токен, chat_id, получатель нажал /start; с российского хостинга API Telegram обычно доступен, но проверьте логи |
| GitHub не триггерит сборку | Токен и вебхук; ветка `main`; событие push |
| Нет бесплатного тарифа | Он и не заявлен; «Пробный» — 170 ₽/30 дней |

## Юридическая оговорка

Amvera — российский хостинг, это плюс для локализации данных по 152-ФЗ. Но сам по себе российский хостинг **не делает проект соответствующим закону**. Для реальных пациентов всё равно нужны:

- согласия на обработку специальной категории данных;
- уведомление Роскомнадзора;
- политика и внутренние документы;
- врачебная тайна по 323-ФЗ;
- защищённый канал уведомлений (лучше МИС/портал или MAX/VK, а не личный Telegram);
- лицензия/МИС, если оказываются медицинские услуги;
- порядок телемедицины по приказу № 193н, если добавляются онлайн-консультации.

Для домашки с вымышленными данными достаточно демо-контура. Подробный чек-лист — в [DEPLOY.md](DEPLOY.md#9-законодательство-рф-что-нужно-знать-перед-реальным-запуском).
