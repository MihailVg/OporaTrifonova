# Деплой «Опоры»: быстро, бесплатно и с оглядкой на законодательство РФ

> ⚠️ **Render в России заблокирован по IP-диапазону.** Сайт на `*.onrender.com` не откроется у пользователей в РФ. Для проекта, который должен работать в России, используйте **[DEPLOY-AMVERA.md](DEPLOY-AMVERA.md)** — Amvera Cloud, российский аналог Render (от ~170–290 ₽/мес). Разделы про Render ниже оставлены для зарубежного демо и как архив.

Это практическая инструкция для учебного проекта. Разделим два разных сценария:

| Сценарий | Где | Данные | Законность |
|---|---|---|---|
| **Демо для домашки в РФ** | Amvera Cloud (РФ, от ~170–290 ₽/мес) | Вымышленные пациенты | Учебный проект; реальные медицинские данные сюда не загружать |
| **Демо за рубежом** | Render (бесплатно; в РФ заблокирован) | Вымышленные пациенты | Для пользователей вне РФ |
| **Боевой контур** | Хостинг и PostgreSQL в РФ + защищённый канал | Реальные пациенты | Нужны 152-ФЗ, 323-ФЗ, уведомление РКН, согласия, лицензия/МИС и т.д. |

**Главный вывод:** для сайта, который должен открываться в России, зарубежный Render не подходит — он заблокирован. Бесплатного и одновременно стабильного контура для Node.js в РФ сейчас нет; самый близкий вариант — Amvera за небольшую плату. Для реальной онлайн-поликлиники бесплатного и соответствующего 152-ФЗ контура нет: нужен хостинг и база в России, юридическая подготовка и, как правило, платная инфраструктура.

> Я не юрист. Ниже — практический чек-лист и ссылки на нормы, а не юридическое заключение. Перед реальным запуском покажите проект юристу, работающему с медицинскими персональными данными.

## 0. Что получится

- Для РФ: сайт на техническом домене Amvera или своём домене; данные — в постоянном хранилище `/data` (PGlite) или PostgreSQL в РФ.

- Врач входит на `/doctor` по паролю, видит графики, сигналы и сообщения.

- Данные можно хранить в PostgreSQL, чтобы они не пропадали при перезапуске.

Время: 15–30 минут. Деньги: для РФ — от ~170–290 ₽/мес (Amvera); зарубежный Render — 0 ₽, но в РФ недоступен. Карта для Render/Neon обычно не нужна, но сервисы могут менять правила.

## 2. Telegram: бот и chat_id

### 2.1. Создать бота

1. Откройте **@BotFather** в Telegram.
2. Отправьте `/newbot`.
3. Придумайте имя (например, `Опора — уведомления`) и username, заканчивающийся на `bot` (например, `opora_sonya_bot`).
4. BotFather пришлёт токен вида `123456789:AA...`. Это **секрет**. Не публикуйте его, не коммитьте в Git. Если токен утёк — `/revoke` у BotFather.

### 2.2. Получатель должен запустить бота

Бот **не может написать первым**. @Sson1ta должна:

1. Открыть ссылку `https://t.me/<username_бота>`.
2. Нажать **Start** (или отправить любое сообщение).

Без этого Telegram вернёт `403 Forbidden: bot can't initiate conversation with a user` или `chat not found`.

### 2.3. Узнать chat_id

Самый простой способ:

1. @Sson1ta пишет **@userinfobot**.
2. Бот присылает её числовой ID, например `123456789`.

Альтернатива через API:

1. Откройте в браузере:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
2. Найдите фрагмент:
   ```json
   "chat": { "id": 123456789, "first_name": "..." }
   ```
3. Число `123456789` — это `TELEGRAM_CHAT_ID`.

Если несколько получателей — перечислите ID через запятую:

```env
TELEGRAM_CHAT_ID=123456789,987654321
```

### 2.4. Проверить локально

```bash
cp .env.example .env
# заполните TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
npm run test:telegram
```

Или после деплоя: `/doctor` → «Настройки» → «Отправить тестовое сообщение».

Так выглядит сигнал:

```text
🚨 Тревожный сигнал

Пациент: Мария Демидова
Код: OP-DEMO-2026
Боль: 10/10
Время: 11 ноября в 14:47
Телефон: +7 (900) 000-00-01
Комментарий: Боль усилилась, таблетка не помогла

Опора · дневник боли · учебный демо-проект
```

> Для реальной работы личный Telegram врача — плохой медицинский канал: данные уходят за границу, сообщения хранятся на серверах Telegram, а уведомление может попасть на экран блокировки. Для боевого контура используйте защищённый портал/МИС или российский MAX/VK, а имена и диагнозы в push-уведомлениях минимизируйте.

## 4. Render: зарубежный демо-деплой (в РФ заблокирован)

> Для сайта, который должен открываться в России, этот раздел не подходит: `onrender.com` заблокирован по IP. Используйте [DEPLOY-AMVERA.md](DEPLOY-AMVERA.md). Ниже — для зарубежных пользователей и как архив.

### Вариант A — Blueprint (рекомендую)

1. Войдите в Render через GitHub.
2. **New** → **Blueprint**.
3. Выберите репозиторий. Render увидит `render.yaml`.
4. Нажмите **Apply**.
5. Заполните секреты, которые попросит Render:

| Переменная | Что ввести |
|---|---|
| `DOCTOR_PASSWORD` | Ваш пароль для `/doctor`, минимум 12 символов, лучше менеджер паролей |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather |
| `TELEGRAM_CHAT_ID` | Числовой ID @Sson1ta (можно несколько через запятую) |

`SESSION_SECRET` Render сгенерирует сам (`generateValue: true`).  
`NODE_ENV=production`, `TZ=Europe/Kaliningrad`, `ALARM_COOLDOWN_SEC=120` уже заданы.

6. Дождитесь статуса **Live** (3–5 минут).
7. Откройте выданный URL.

### Вариант B — вручную

1. **New** → **Web Service**.
2. Подключите GitHub-репозиторий.
3. Настройки:
   - **Name:** `opora-clinic`
   - **Region:** Frankfurt (ближе к РФ, чем США)
   - **Runtime:** Node
   - **Build Command:** `npm ci`
   - **Start Command:** `npm start`
   - **Plan:** Free
   - **Health Check Path:** `/api/health`
4. **Environment** → добавьте:

```env
NODE_ENV=production
NODE_VERSION=22
TZ=Europe/Kaliningrad
ALARM_COOLDOWN_SEC=120
DOCTOR_PASSWORD=<ваш пароль>
SESSION_SECRET=<случайная строка>
TELEGRAM_BOT_TOKEN=<токен>
TELEGRAM_CHAT_ID=<id>
```

Сгенерировать `SESSION_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

5. **Create Web Service**.

### Что нужно знать про бесплатный Render

- Инстанс **засыпает после ~15 минут** без запросов; первый запрос после сна — 30–60 секунд.
- 750 часов в месяц — одного сервиса на 24/7 хватает (744 часа), но лучше не держать лишние сервисы.
- Постоянного диска на Free нет: файл PGlite в `/app/data` может исчезнуть при перезапуске/деплое. Для сохранения данных подключите Neon (раздел 5) или платный диск Render.
- Если нужен «тёплый» демо-стенд, можно настроить бесплатный пинг `https://<url>/api/health` раз в 10 минут через cron-job.org. Это расходует часы инстанса; для домашки обычно не требуется.
- HTTPS Render выдаёт автоматически.

## 5. Neon: чтобы данные не пропадали

> Для российского контура используйте постоянное хранилище Amvera (`/data`) или PostgreSQL в РФ. Neon — зарубежный сервис, для реальных медицинских данных не подходит.

Бесплатный Render без диска теряет PGlite-файл при перезапуске. Для домашки это может быть незаметно в течение одной демонстрации, но лучше сразу подключить внешний PostgreSQL.

### 5.1. Создать базу

1. Зарегистрируйтесь на <https://neon.tech> через GitHub (карта не нужна).
2. **New Project**:
   - имя: `opora`;
   - регион: **Frankfurt** (ближе к Render Frankfurt);
   - PostgreSQL 16/17 — подойдёт.
3. В проекте нажмите **Connect** и скопируйте **Pooled connection string**. Он выглядит так:

```text
postgresql://neondb_owner:ПАРОЛЬ@ep-xxxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
```

4. В Render: **Environment** → **Add Environment Variable**:
   - Key: `DATABASE_URL`
   - Value: скопированная строка (с `-pooler` и `sslmode=require`).
5. **Manual Deploy** → **Deploy latest commit** (или дождитесь автодеплоя).

При старте приложение само создаст таблицы. В логах будет:

```text
[db] Хранилище готово: postgres
```

Проверьте `/api/health` — там должно быть `"db":"postgres"`.

### 5.2. Ограничения бесплатного Neon

- 0,5 ГБ хранилища, один проект — для домашки более чем достаточно.
- База «просыпается» после простоя; первый запрос может быть чуть медленнее.
- Лимиты могут меняться; проверьте актуальные условия на сайте.

### 5.3. Альтернативы

- **Supabase** — бесплатный PostgreSQL; берите **Session Pooler** (IPv4) строку, а не прямой IPv6-хост. Бесплатный проект может засыпать после недели простоя.
- **Render PostgreSQL** — удобно, но бесплатный план ограничен по времени; для постоянной работы платный.
- **PostgreSQL в РФ** — для боевого контура (Yandex Cloud, VK Cloud, Selectel, Timeweb Cloud, Cloud.ru).

> Для реальных медицинских данных зарубежные Render/Neon не подходят: база должна быть в РФ (ч. 5 ст. 18 152-ФЗ). Это допустимо только для вымышленных демо-данных.


## 9. Законодательство РФ: что нужно знать перед реальным запуском

### 9.1. 152-ФЗ «О персональных данных»

Медицинские сведения — **специальная категория** персональных данных (ст. 10). Это значит:

- нужно **отдельное согласие** на обработку данных о здоровье; для специальной категории закон говорит о письменной форме — электронная галочка в демо не заменяет полноценное согласие для реальной клиники;
- согласие должно быть конкретным, предметным, информированным и сознательным; нельзя «зашить» его в пользовательское соглашение и поставить галочку заранее;
- оператор обязан опубликовать **политику обработки ПДн** (ст. 18.1) — в проекте есть шаблон `/privacy`;
- до начала обработки оператор **уведомляет Роскомнадзор** (ст. 22) через электронную форму на <https://pd.rkn.gov.ru/>; для клиники это делается до запуска;
- **локализация баз данных**: с 1 июля 2025 года (в редакции 23-ФЗ) при сборе ПДн граждан РФ нельзя использовать зарубежные базы; база должна быть в России (ч. 5 ст. 18). Render/Neon/иностранные SaaS для реальных данных не подходят;
- **трансграничная передача** (ст. 12): до передачи в иностранный сервис нужно уведомить РКН и получить согласие субъекта; РКН может запретить передачу. Telegram, WhatsApp, зарубежный хостинг — всё это трансграничная история;
- нужны меры безопасности (ст. 19), ответственный за организацию обработки, внутренние документы, ограничение доступа, журналирование, резервное копирование, сроки хранения и уничтожения;
- у субъекта есть права на доступ, уточнение, удаление и отзыв согласия; отвечать нужно в сроки, установленные законом;
- за нарушения — административная ответственность по ст. 13.11 КоАП. После изменений 420-ФЗ (вступили в силу 30.05.2025) штрафы за утечку специальной категории — **10–15 млн ₽**, при повторе — до 3% годовой выручки; возможна и уголовная ответственность по ст. 272.1 УК РФ. Это не «страшилка», а причина не хранить реальные медданные в демо-контуре.

**Что это значит для проекта:** демо с вымышленными именами и зарубежным хостингом — учебный макет. Реальная клиника должна поднять контур в РФ, оформить согласия и документы, уведомить РКН и использовать защищённые каналы.

### 9.2. 323-ФЗ «Об основах охраны здоровья граждан»

- **Врачебная тайна** (ст. 13): сведения о факте обращения, диагнозе, лечении и т.п. нельзя раскрывать третьим лицам без законных оснований. Личный Telegram врача, куда приходит имя и уровень боли, — не защищённая медицинская система. Для реальной работы — МИС/защищённый портал, отдельный рабочий аккаунт, 2FA, минимизация данных в уведомлениях.
- **Информированное добровольное согласие** (ст. 20) на медицинское вмешательство — отдельно от согласия на обработку ПДн.
- **Телемедицина** (ст. 36.2): дистанционные консультации регулируются отдельно. С 1 сентября 2025 года действует **Порядок организации и оказания медицинской помощи с применением телемедицинских технологий**, утверждённый приказом Минздрава России от 11.04.2025 № 193н (зарегистрирован 15.05.2025; заменил 965н). Ключевое:
  - помощь оказывается в рамках лицензии медицинской организации;
  - нужна идентификация пациента и врача (ЕСИА/ФРМР и т.п.);
  - используются защищённые каналы и медицинские информационные системы;
  - нельзя «с нуля» ставить диагноз и назначать лечение без очного осмотра; электронные рецепты — после очного диагноза;
  - консультации документируются, записи хранятся.
- **Наш сайт не является телемедицинской платформой**: это дневник и уведомления. Здесь нет диагноза, назначений и рецептов. Если захотите добавить онлайн-консультации, нужна лицензированная МИС/платформа и соблюдение 193н, а не просто видеозвонок.

### 9.4. Иностранные мессенджеры

- **Telegram** — иностранный сервис. Передача имени и сведений о боли — это специальная категория ПДн и трансграничная передача. Для реальной клиники высокий риск по 152-ФЗ и врачебной тайне.
- **WhatsApp** принадлежит Meta, признанной в РФ экстремистской организацией; для медицинской коммуникации не используйте.
- С 2025 года действуют ограничения на иностранные мессенджеры для отдельных категорий организаций (41-ФЗ: банки, операторы связи, доставка, госорганы и др.). Прямо в перечне «медицинские организации» могут быть не названы, но это не отменяет 152-ФЗ и врачебную тайну. Не стройте боевой канал на Telegram только потому, что прямого запрета для клиник нет.
- Для реального контура: **MAX** (российский мессенджер, есть Bot API), **VK**, защищённый портал пациента или МИС. Даже там имена и диагнозы в уведомлениях минимизируйте.
- Если очень нужен Telegram, юридически безопаснее отправлять **обезличенный код** и просить врача открыть защищённый кабинет, а не имя+боль. Но для домашки требование «с именем» выполнено в демо.

### 9.5. Что сделать перед реальным запуском: чек-лист

**Юридический блок**

- [ ] Определить оператора ПДн (ООО/ИП), ответственного за обработку, издать приказ и политику.
- [ ] Провести инвентаризацию данных и процессов, составить модель угроз/оценку вреда.
- [ ] Подготовить и получать согласия: на обработку ПДн, на данные о здоровье, на трансграничную передачу (если она останется), на медицинское вмешательство (если применимо).
- [ ] Уведомить Роскомнадзор о намерении обрабатывать ПДн до запуска.
- [ ] Если данные в иностранном сервисе — оценить и, скорее всего, отказаться; обеспечить локализацию в РФ.
- [ ] Оформить договоры с подрядчиками (хостинг, БД, уведомления), поручение обработки, конфиденциальность.
- [ ] Проверить лицензию/МИС, правила платных услуг, рекламу, врачебную тайну.
- [ ] Настроить сроки хранения, уничтожение, бэкапы, журналы доступа, реакцию на инциденты.
- [ ] Обучить сотрудников; запретить личные мессенджеры для медданных.

**Технический блок**

- [ ] Хостинг и PostgreSQL в РФ (Yandex Cloud, VK Cloud, Selectel, Timeweb, Cloud.ru).
- [ ] Домен `.ru`, HTTPS, WAF/ограничение частоты, резервные копии в РФ.
- [ ] Защищённый канал уведомлений: MAX/VK/МИС/портал; без лишних ПДн в push.
- [ ] Отдельные рабочие аккаунты врача, 2FA, менеджер паролей, device lock.
- [ ] Шифрование/сегментация, ограничение доступа, журналирование.
- [ ] Тестирование восстановления и удаления данных.
- [ ] Обновить `shared/site.js`: `demo: false`, реальные контакты и лицензия; убрать `noindex`.
- [ ] Проверить, что в боевой базе нет демо-пациентов.

**Организационный блок**

- [ ] Назначить ответственного за ПДн и контакт для обращений.
- [ ] Регламент ответа на запросы субъектов (доступ, удаление, отзыв согласия).
- [ ] Регламент инцидентов: кто, что и в какие сроки уведомляет.
- [ ] Договор с врачом/сотрудниками о конфиденциальности.
- [ ] Проверка подрядчиков и их местонахождения.

### 9.6. Почему нельзя просто «сделать бесплатно и по закону»

- Зарубежный хостинг с реальными медданными нарушает локализацию и создаёт риск трансграничной передачи.
- Бесплатные тарифы зарубежных PaaS не дают договора, российских дата-центров и гарантий для медицинских данных.
- Бесплатный российский хостинг для медицинского контура — редкость; обычно это trial/грант, который заканчивается.
- Лицензия, МИС, юридические документы и сопровождение стоят денег.

Поэтому честная схема такая:

1. **Сейчас** — бесплатное демо с вымышленными данными для сдачи домашки.
2. **Потом, если проект станет реальным** — платный контур в РФ + юрист + лицензия/МИС.

## 10. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Render долго не отвечает | Free-инстанс спал; подождите 30–60 с и обновите |
| `502` / `Application failed to respond` | Логи Render → Build/Deploy; проверьте `npm ci`, `npm start`, `PORT` |
| Build падает на `npm ci` | В репозитории должен быть `package-lock.json`; Node 22; удалите lock и `npm install` локально, закоммитьте заново |
| Telegram: `chat not found` | Получатель не нажал /start; неверный `chat_id`; бот удалён |
| Telegram: `Forbidden: bot was blocked by the user` | Получатель заблокировал бота; разблокировать и /start |
| Telegram: `Unauthorized` | Неверный токен; пробелы/кавычки в env; перевыпустите токен |
| Тестовое сообщение не приходит | Проверьте env в Render, нажмите Manual Deploy после изменения env |
| Данные пропали после перезапуска | PGlite на Free; подключите `DATABASE_URL` (Neon) или платный диск |
| `[db] PostgreSQL недоступен` | Неверная `DATABASE_URL`, SSL, база спит; проверьте строку и `sslmode=require` |
| В консоли ошибка Kaspersky | Расширение Kaspersky блокируется CSP; на работу сайта не влияет |
| Не работает тревожная кнопка | Вы вошли как пациентка? Есть ли `TELEGRAM_*`? Смотрите `/api/health` и `telegram` |
| «Слишком много сигналов» | Кулдаун 120 секунд; это защита от спама |
| После смены env ничего не изменилось | Render применяет env только после рестарта/деплоя |

Полезные команды локально:

```bash
npm test                 # API-тесты
npm run dev              # запуск с watch
npm run seed             # демо-пациентка
npm run test:telegram    # реальное тестовое сообщение
```

Логи Render: **Logs** → выберите сервис. Тела запросов с персональными данными приложение не логирует.
